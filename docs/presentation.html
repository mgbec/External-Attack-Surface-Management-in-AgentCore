The problem

You can't defend what you don't know you own

Shadow assets

Forgotten subdomains, staging boxes, and old cloud resources sit exposed with no one watching them.

No single inventory

Real orgs own many domains and IP ranges across teams, clouds, and acquisitions — there's no one list.

Commercial EASM is pricey

Enterprise platforms cost thousands a month. Teams want the same visibility for a fraction of that.

The attack surface is the set of assets an attacker can reach from the internet. The hard part isn't attacking it — it's discovering and attributing it.

The approach

One seed set in → a scored inventory + findings out

  • You provide root domains (plus optional org names / IP ranges).
  • The tool expands each seed into the full asset list — you don't need an inventory up front, the inventory is the output.
  • Every asset gets a confidence score for whether it really belongs to the org.
  • Deterministic rules surface exposures; a small LLM triages and writes the report.

How discovery works

Passive sources — query third parties, not the target

Certificate Transparency

Public cert logs (crt.sh) reveal subdomains — the single biggest source of discovery. Free.

DNS

Resolve hosts to IPs, follow CNAMEs, catch dangling records (subdomain-takeover risk). Free.

RDAP / ASN

Pivot IPs to the netblocks and orgs that own them, and domains to their registrant. Free.

TLS inspection

Read the cert: expiry, weak crypto, and SANs that reveal even more hostnames (fed back in).

HTTP inspection

Ordinary requests surface missing security headers and version-leaking banners.

Shodan / Censys

Optional port/service data from a third party's scans. Off by default, behind free-tier keys.

Safe by design: no intrusive scanning — only public data and normal, browser-like web traffic.

The engine

Discovery is recursive, and it terminates cheaply

seed domain→ CT logs → subdomains→ DNS → IPs→ RDAP → netblock
TLS cert → new SANs↺ feed hostnames back to CT/DNS
  • A cert reveals a subdomain → resolve it → its IP reveals a netblock → loop.
  • Bounded by max depth, max assets, concurrency, and per-request timeouts — so a scan finishes fast and stays cheap.
The hard problem

Attribution: does this asset actually belong to you?

  • Finding more assets is easy. Knowing which are really yours is the hard part — pivots can pull in neighbors.
  • Each asset records which seeds led to it. Corroboration across multiple independent seeds raises confidence.
  • Score blends method strength, seed corroboration, and depth into a 0–1 value.
  • Below 0.5 → flagged for human review, never asserted as yours automatically.

Architecture

Deterministic engine + a thin, cheap LLM layer

The pipeline (pure Python)

Does all the network discovery, dedup, attribution scoring, and rule-based findings. Reproducible and free — no tokens spent here.

Strands agent on AgentCore Runtime

The LLM only sees a compact JSON summary: it triages, prioritizes, and writes the report. It never invents findings.

from bedrock_agentcore import BedrockAgentCoreApp
from strands import Agent
app = BedrockAgentCoreApp()

@app.entrypoint
async def handler(request):          # {"seeds": {"domains": [...]}}
    result = await run_scan(config)  # deterministic — no model tokens
    yield {"type": "scan_result", "data": result.to_dict()}
    agent = Agent(model="claude-3-5-haiku", system_prompt=ANALYST)
    async for e in agent.stream_async(summary):   # cheap triage + report
        yield e

What it catches

Exposure findings, severity-ranked

High

Expired certs · dangling CNAMEs (takeover) · exposed Redis/Mongo/RDP/Telnet

Medium

Expiring-soon certs · self-signed · weak signature algorithms · exposed SSH/DB ports

Low

Missing HSTS/CSP · version-leaking banners · no HTTPS redirect

Reporting

Self-contained HTML + Markdown report, with a change-diff vs the previous scan

Rules are deterministic — objective and reproducible. The model prioritizes by real-world risk; it doesn't fabricate.
